# Local route avoidance

`neurovector/avoidance.hpp` provides a C++20 decision layer. It does not operate motors or upload a flight mission. Pass positions and velocities in one local ENU frame (east, north, up; metres and metres/second). `remaining_route` contains only future waypoints, in flight order. All observation timestamps use the same monotonic clock as `now_s`. Set `sensors_ready=true` only after the live pipeline is healthy and update `observations_at_s` on every valid observation frame, including frames containing no detections. Missing or stale heartbeat returns `hold`; an empty obstacle list alone is not evidence that the camera is working.

`decide()` returns `proceed`, `slow`, `hold`, or `request_replan`. Its speed is an advisory ceiling for an existing controller, not a position/velocity setpoint. `hold` means brake and maintain position under the flight controller's supervision. The controller remains responsible for emergency stabilization.

Every input requires a fresh `state` containing the autopilot mode, valid pose,
velocity and attitude, and healthy control authority. Unknown mode or stale state
blocks motion. Current braking travel must fit outside the protected facade and
no-fly zones even when the planned route points away from them.

For landing, set `state.mode=FlightMode::landing` and supply calibrated downward surface
observations, full descent coverage and obstacles. Missing support or hazards below
return `hold` before any descent is permitted. See [landing safety](landing-safety.md).

Obstacle priority is 1 for people/body parts/animals, 2 for vehicles and other objects, and 3 for leaves. Every priority can cause a physical collision. `Decision.threat_order` returns all relevant obstacle indices in order; `obstacle_index` identifies the first. Ordering is deterministic: immediate collision first, then priority, collision entry time, current distance, and input index. A lower priority obstacle can still block the action selected for a higher priority obstacle. Beyond the common collision envelope, priority 1 adds twice the clearance margin and uses 1.5 times the caution horizon; priority 2 adds one clearance margin and uses the normal horizon; priority 3 adds no extra caution margin and uses 0.75 times the caution horizon. All three retain the same physical collision margin and full emergency prediction horizon.

The decision checks the forward route corridor and predicts moving-sphere intersections using relative motion along every remaining route segment within the configured horizon. It separately checks current vehicle velocity for an immediate physical collision outside the route corridor. Braking distance includes `speed² / (2 × deceleration)`, reaction travel, and clearance. An obstacle outside the corridor is ignored unless its motion or physical proximity creates a collision risk.

Missing/old depth, unknown pose or motion, and low confidence cause a hold when the obstacle may affect the nearby corridor. A scalar radial distance alone cannot establish that an obstacle is off the route. Stale or unreliable unlocalized range always causes a hold, including an old far-distance reading. For stale, low-confidence, or unknown-motion localized obstacles, the potentially reachable region expands by `unknown_obstacle_speed_mps × (observation age + caution horizon)` (bounded to 100km). Choose that speed bound for the operating environment; objects that can exceed it require a larger configured bound. A reachable region intersecting the nearby route blocks movement. Invalid or excessive inputs return `hold`. Limits are 256 remaining waypoints, 128 obstacles, 64 ENU no-fly boxes, and 64 coverage boxes.

For a blocked route, the layer considers left and right lateral candidates at the current altitude. Every complete candidate segment must fit inside a fresh coverage box after accounting for vehicle radius and clearance. Coverage must represent observed free space with a complete obstacle inventory; it must not be fabricated from the camera field of view. Each segment is checked against every supplied obstacle's predicted motion, every expanded no-fly box, and the optional exterior facade half-space. Candidates extending beyond the prediction horizon, using stale/unlocalized obstacles, or lacking coverage are not returned. No automatic climb or descent is introduced.

A returned `detour` remains `request_replan`: obtain backend and drone mission cross-validation and recheck live obstacles before flight. A missing detour is an explicit request for a new plan, not evidence that either side is clear. This bounded left/right search does not claim a globally optimal or always available escape path.

For window delivery, set `facade` with a unit horizontal outward normal and at least 2m standoff. The whole vehicle clearance envelope must remain outside that plane. `Facade.minimum_standoff_m` is the protected body-clearance distance, while the backend window target specifies a vehicle-centre standoff. Therefore the planned centre must satisfy `backend standoff >= facade minimum + drone radius + clearance`. With the default 0.5m radius and 0.5m clearance and a 2m protected facade distance, request at least a 3m centre standoff; passing a 2m backend centre target with a 2m facade minimum correctly reports a violation. `window_handoff=true` always requests a stationary exterior hold. This layer never enters a window, chooses an interior destination, or changes altitude for delivery.

`project_detection()` converts a detection box centre and **radial** distance to ENU. It normalizes the OpenCV camera ray `(right, down, forward)` before multiplying by distance, then applies a validated proper orthonormal camera-to-ENU rotation and camera-origin translation. Use physical intrinsics for the undistorted image and current resolution. For horizontally mirrored detections set `Camera.mirrored=true`; the helper restores the original pixel X before projection. Do not also reflect the principal point, which would apply mirroring twice. The camera pose and detection must be synchronized by the caller. Missing depth, invalid boxes/intrinsics, or unknown pose return no position. Preserve `position_known=false` and the available range in the obstacle passed to `decide()`; never substitute an origin coordinate.
